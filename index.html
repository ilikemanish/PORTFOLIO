Online Book Store Analysis

A PostgreSQL deep dive into 20 business questions spanning books, customers, orders, and inventory for a fictional online bookstore.

01

The Problem

The store had plenty of raw data — books, genres, customers, orders — but no single source of truth. Which genres sell best? Who are the top 5 spenders? Which inventory is running low?

02

The Approach

I loaded four CSV tables into PostgreSQL, established primary/foreign keys, and wrote progressive SQL from simple joins to correlated subqueries and window functions.

SQL
-- Top 5 customers by total spend
SELECT c.name,
       SUM(o.total_amount) AS spend
FROM customers c
JOIN orders o ON o.customer_id = c.id
GROUP BY c.name
ORDER BY spend DESC
LIMIT 5;

NumPy Sales Analysis

Turning a slow, loop-heavy sales pipeline into a blazing-fast vectorized workflow — with the same business output.

01

The Problem

The original script processed 2 million rows using Python loops. It took over 40 minutes to run and was holding up the entire reporting pipeline.

02

The Rewrite

I replaced every loop with a NumPy vectorized operation and re-used boolean masks for filtering.

Python
# Before: Python loop (~40 min)
for i in range(len(sales)):
    if sales[i] > threshold:
        total += sales[i]

# After: NumPy vectorized (~3 min)
total = sales[sales > threshold].sum()
03

Performance Comparison

100%
Loop
10%
NumPy
Insight: A 10x speedup means the reporting pipeline now runs every hour instead of once a day.
04

Same Business Truth

The output metrics — top products, regional totals, and month-over-month growth — were identical to the old script. Only the runtime changed.

05

The Final Result

Result: A reusable NumPy template for any large-array analysis — cutting runtime from 40 minutes to under 3.
